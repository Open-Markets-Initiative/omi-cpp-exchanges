# Nasdaq Stock Market Session Simulator

Generated exchange simulator for Nasdaq Stock Market Session: an order-entry gateway, a price-time matching engine running the trading day,
market data feed publishers, the replay services a client logs into (Glimpse, TotalViewTcp),
and traders that exercise the exchange end to end. Every link between two components carries
framed Nasdaq.NsmEquities.MatchingEngine.Ipc.v2026 messages: the gateway owns the client sockets, the engine owns the
book, and each feed owns its market data.

The components are generated once, into `common/`, and deployed three ways - `process/`, one binary with a thread per component, `system/`, a process per component on this host, `distributed/`, a process per component across machines. Each directory has a ReadMe of its own.

## Layout

```
CMakeLists.txt         every target: the single binary, a binary per component, the tests
Dockerfile             the venue as one image; distributed/compose.yaml runs a component per container
simulator.ini          runtime endpoints, read at process start (docker/ holds the container copy)
common/                everything the deployments share, generated once
  protocols/           the generated structs, messages and sessions of each protocol
  engine/ traders/     the matching engine and the venue's own traders
  run/                 the links: a queue, a ring in shared memory, a socket
process/               one binary, a thread per component - deterministic, the reference
system/                a process per component on one host, rings in shared memory
distributed/           a process per component across machines, Tcp, tiers that fail apart
```

Each of `process/`, `system/`, `distributed/` has a ReadMe saying what it is and what it is not; the separated ones have a `launch.sh`
and a `verify.sh` that runs the venue and checks what its components carried.

## Trading Day

The engine runs `Nasdaq.NsmEquities.Equities.Session.TradingSession`: each phase of the day decides whether an order
trades, waits for the next cross, or is refused. Each change of phase is announced on the
internal messaging, and so is each cross completed, with the price it crossed at and the
shares that traded there. The day the simulator is generated with:

| Change | Before startup run turn | Served (seconds after start) |
| --- | --- | --- |
| PreOpen | 0 | 0 |
| Halt | 0 | 0 |
| OpeningLockIn | 2 | 25 |
| OpeningLockOut | 3 | 28 |
| OpeningLate | 4 | 29 |
| Open | 4 | 30 |
| Postpone | 5 | 45 |
| Halt | 5 | 60 |
| Resume | 7 | 85 |
| Quote | 7 | 90 |
| Resume | 8 | 110 |
| Halt | 8 | 120 |
| Quote | 9 | 140 |
| Resume | 10 | 150 |
| PreClose | 14 | 240 |
| ClosingLockOut | 16 | 265 |
| ClosingFreeze | 17 | 268 |
| Close | 18 | 270 |
| ExtendedTradingCloseEnd | 19 | 275 |
| End | 20 | 300 |

A turn past the run's last is made after it. The startup run asks for each change between its
turns, so it is the same every run; a served venue makes them on the clock.

While an auction collects, the day asks the engine what it would cross at, and the engine
answers on the internal messaging with the price, the shares that would pair there, and those
left over and on which side. The startup run asks once a turn; a served venue asks on this
cadence, in seconds:

| Auction | First ask after the collection starts | Then every | Then every, over the last part | Last part |
| --- | --- | --- | --- | --- |
| Opening, early, from OpeningLockIn | 0 | 10 | - | - |
| Opening, from OpeningLockOut | 0 | 1 | - | - |
| Intraday, from Halt (LUDP) | 1 | 1 | - | - |
| Intraday, from Quote | 1 | 1 | - | - |
| Closing, early, from PreClose | 0 | 10 | - | - |
| Closing, from ClosingLockOut | 0 | 1 | - | - |
| Extended, from Close | 5 | 5 | - | - |

A stage "from" a change is asked about from that change, its first ask counted from it, until
the next change that does not go on collecting for its auction; an auction collecting before
its first stage starts is not asked about.

Its matching engine model states the Order Imbalance Indicator, so the engine answers with three
prices: what the auction would cross at over its own orders alone (the Far price), over those and
the book trading on (the Near price), and the Current Reference Price the paired and left over
shares are counted at - over the auction's own orders, among the prices at or within the best bid
and offer of the book trading on. A halt's cross answers its one price in all three, and an early
ask is answered with no Far and no Near.

## Matching Rules

Beside price and time the engine applies the rules below, each as its matching engine model states it:
where the venue states the rule, the venue's own words, what the engine does of it, and what of that is
the simulator's judgement, not built, or measured on the venue's own feed.

`Nasdaq.NsmEquities.Equities.MatchingEngine`

**PostOnly** - Nasdaq Equity 4, Rule 4702(b)(4)

- The venue: A Post-Only Order is "an Order Type designed to have its price adjusted as needed to post to the Nasdaq Book"; it "will execute if ... it is priced at $1.00 or more and the value of price improvement associated with executing against an Order on the Nasdaq Book (as measured against the original limit price of the Order) equals or exceeds $0.01 per share".
- The engine: It trades as it arrives only with what betters its limit by a price increment, and what is left posts a minimum price increment inside the best displayed order it would lock or cross - or at its limit where only orders the book does not show are in its way.
- Judgement: Below $1.00 the rule weighs fees and rebates the simulator has none of, and the increment stands in for them.
- The venue: Where it "would lock or cross a displayed Order at its displayed price on the Nasdaq Book, the Post Only Order may either be adjusted or be cancelled back to the Participant, depending on the Participant's choice".
- The engine: A client whose port has it cancelled - the declaration's Client PostOnly Cancel - has such an order accepted as entered and cancelled, OUCH's cancel reason G; an IOC one is cancelled as any IOC is.
- Not built: A quotation of another market, which the rule also keeps it from locking, and so OUCH's cancel reason F.

**MinimumQuantity** - Nasdaq Equity 4, Rule 4703(e)

- The engine: An order names the fewest shares it trades. It executes as it arrives only where at least that many rest within its price, posts unseen otherwise, and once posted trades only with an order of at least its minimum; it takes no part in a cross.
- Judgement: Of the rule's two ways of meeting the minimum on entry - against several orders, or against each of one or more - OUCH names none, and the first is taken.
- The venue: OUCH 5.0, Appendix A, tag 3: "MinQty must be a round lot."

**Pegged** - Nasdaq Equity 4, Rule 4703(d)

- The engine: A Midpoint Peg follows the midpoint of the best bid and offer, is never shown, and takes no part in a cross; an order pegged to the best price on its own side or the other follows that, by its offset.
- Judgement: Nasdaq prices a peg from the national best bid and offer; the simulator has no other market, and its own best shown bid and offer stand in.
- Not built: A Market Maker Peg, and OUCH's PriceType m, which the document does not explain: an order carrying either is refused as Invalid Peg Type.
- The venue: "An Order with Pegging receives a new timestamp whenever its price is updated"; OUCH 5.0: "A Priority Update Message is sent whenever priority of the order has been changed by the system", and "As a result of the updated priority, a new order reference number will be assigned".
- The engine: A peg the engine reprices rests again behind what rests at its new price, under a new id, and its owner is told an Order Priority Update with the new price and order reference number. One with no midpoint to follow leaves the book and is told so again once it is re-entered, at whatever price.

**Hidden** - Nasdaq Equity 4, Rule 4757(a)(1)

- The venue: The price/display/time algorithm: "Better priced Orders will be presented for execution first", "Equally priced Orders with a Display Attribute will be ranked in time priority", and "Orders with a Non-Display Attribute, including the Non-Displayed portion of an Order with Reserve Size, will be ranked in time priority".
- The engine: An order the book does not show rests and trades unseen, behind every shown order at its price and in time order among the unseen; the feed publishes nothing of it but its trades.
- Measured: Nasdaq's TotalView-ITCH feed of 2026-08-20, the whole day (898,523,816 messages): each of the 6,615,759 Trade Messages of an order the feed never showed carries Order Reference Number 0 and Buy/Sell Indicator B.

**Expiring** - Nasdaq Equity 4, Rule 4703(a)

- The venue: An Order may deactivate at "a specific time identified by the Participant; provided, however, that an Order specifying an expire time beyond 8:00 p.m. ET will be cancelled at the conclusion of the Day Sesson at 8:00 p.m. ET".
- The engine: A GTT order expires by its own time, OUCH's ExpireTime option in seconds to live, or at the end of the day where that is sooner; one with no expire time, or one already past, is refused.

**CrossOnly** - Nasdaq Equity 4, Rules 4702(b)(8)-(13), 4752, 4753 and 4754

- The venue: OUCH 5.0, of an order whose cancel waits for its cross (Cancel Pending): "any unexecuted portion of this order will automatically be canceled immediately after the cross completes".
- The engine: An order for one cross alone - the Opening, the Closing or a Halt Cross - waits aside until that cross collects, joins it, and what is left of it once the cross completes is canceled. The book never shows one.
- The venue: OUCH 5.0, Cancel Order Reason: "'H' Halted. The on-open order was canceled because the symbol remained halted after the opening cross completed."
- The engine: A security halted as the day's Opening Cross completes takes no part in it: each order for the Opening Cross alone is canceled, its owner told 'H', and its Opening Cross is done for the day, so an on-open order entered once the security is released is refused as one entered after the opening.
- Judgement: That Nasdaq does not display its on-open and on-close orders is the simulator's knowledge of the venue, not a statement of the documents held here.
- Judgement: The retail cross (CrossType R) is not this venue's: OUCH 5.0 states "R = retail (BX only)". An order for it is rejected Invalid Cross Order, as one for any cross the venue does not hold.
- Judgement: A Supplemental Order (CrossType S) executes only against an order that would otherwise route away (Rule 4757(a)(1)(D)). The simulator has no other market, as for every away-market item, so it is rejected Invalid Cross Order rather than rested where nothing could reach it.
- Not built: Extended life (CrossType E) is the rule MidpointExtendedLife's, and the after hours close (CrossType A) the rule ExtendedTradingClose's: an engine stating neither rejects an order for either Invalid Cross Order, as one for a cross it does not hold.
- Measured: Nasdaq's TotalView-ITCH feed of 2026-08-20, the whole day (898,523,816 messages): an Opening Cross is printed for every security, 4,753 with shares and 8,421 with none, and a Closing Cross likewise, 4,269 and 8,905, each with a match number; a Halt Cross only where it traded, all 57 with shares. The System Event of the hour comes first and its cross prints after it.

**Discretion** - Nasdaq Equity 4, Rule 4703(g)

- The venue: "Discretion is an Order Attribute under which an Order has a non-displayed discretionary price range within which the entering Participant is willing to trade". "If, however, an Order with Discretion has a Time-in-Force of IOC upon entry, then the Order will immediately attempt to execute against available liquidity in the discretionary range without first posting to the Nasdaq Book."
- The venue: Once it posts, "if the Nasdaq Market Center observes liquidity available within the discretionary price range, it will generate a Non-Displayed Order with a Time-in-Force of IOC", "with a price equal to the highest price for the Order with Discretion to buy (lowest price for the Order with Discretion to sell) within the discretionary price range and a size equal to the applicable size of the available liquidity on the Nasdaq Book"; in the rule's example, "the remaining 300 shares of the original Order with Discretion will remain posted on the Nasdaq Book".
- The engine: An order with a DiscretionPrice trades at its limit and posts; whenever an order rests within its range - or it rests with liquidity already there - it takes it at the resting orders' prices, its best first, keeping its place with what is left. Its owner hears those fills flagged R; where the book shows it, the feed publishes an Order Cancel of what was taken. An IOC with discretion trades within its range at once.
- Judgement: The book is looked at as an order rests, not as liquidity appears any other way - a reserve refreshed, a peg repriced, an auction's release. ITCH does not say how the shares a Discretionary IOC takes out of a shown order are published; an Order Cancel of them is what leaves the book as the rule describes it.
- Not built: A pegged discretionary price (DiscretionPriceType P, M, R; DiscretionPegOffset), refused as Invalid Peg Type; a reserve order's discretion; discretion with routing.

**ImbalanceOnly** - Nasdaq Equity 4, Rule 4702(b)(10) and (13)

- The venue: An "Imbalance Only Order" or "IO Order" is "an Order entered with a price that may be executed only in the Nasdaq Closing Cross and only against MOC Orders or LOC Orders"; an "Opening Imbalance Only Order" or "OIO Order" one that "may be executed only in the Nasdaq Opening Cross and only against MOO Orders, LOO Orders, or Early Market Hours Orders". OUCH 5.0: HandleInst 'I', "imbalance only (CrossType O and C)".
- The venue: "If the price of an IO Order to buy (sell) is higher than (lower than) the highest bid (lowest offer) on the Nasdaq Book, the price of the IO Order will be modified repeatedly to equal the highest bid (lowest offer) on the Nasdaq Book; provided, however, that the price of the Order will not be moved beyond its stated limit price."
- The engine: It waits for its cross as any order for it does, and takes no part in the cross's price nor in its match: once the cross has crossed, what is left of the cross's own orders at its price is offset by it - one to buy (sell) standing at its limit or at the best bid (offer) of the book where that is lower (higher) - at the cross's price, first entered first filled, and what is left of it is cancelled. Its owner hears its fills flagged M (opening) or L (closing); the cross's own order hears its cross's flag. One for no opening or closing cross is rejected Invalid Cross Order.
- Judgement: It is priced once, at the cross, to the book's best limit before the cross, rather than repeatedly while it waits; the cross's price is found without it, so it never moves the price, where the rule counts it among the interest the price maximizes; and an indication the cross gives while it collects counts it as any order for the cross.
- Not built: An OIO Order against Early Market Hours Orders (Rule 4752); the windows after which an OIO or IO Order may not be cancelled or modified, beyond those of any order for its cross.

**OrderImbalanceIndicator** - Nasdaq Equity 4, Rule 4752(a)(1), (3); Rule 4753(a)(3); Rule 4754(a)(7), (10)

- The venue: "'Current Reference Price' shall mean: (i) The single price that is at or within the current Nasdaq Market Center best bid and offer at which the maximum number of shares of MOO, LOO, OIO, and Early Market Hours orders can be paired. (ii) If more than one price exists under subparagraph (i), the Current Reference Price shall mean the price that minimizes any Imbalance. (iii) If more than one price exists under subparagraph (ii), the Current Reference Price shall mean the entered price at which shares will remain unexecuted in the cross. (iv) If more than one price exists under subparagraph (iii), the Current Reference Price shall mean the price that minimizes the distance from the bid-ask midpoint of the inside quotation prevailing at the time of the order imbalance indicator dissemination."
- The venue: The "'Near Clearing Price' which shall mean the price at which the MOO, LOO, OIO, and Early Market Hours orders and Open Eligible Interest in the Nasdaq Market Center would execute, and (ii) 'Far Clearing Price' which shall mean the price at which the MOO, LOO, OIO, and Early Market Hours orders in the Nasdaq Opening Book would execute"; the Closing Cross's the same of MOC, LOC and IO orders and Close Eligible Interest (Rule 4754(a)(7)).
- The venue: Of a Halt or IPO Cross: "The Far Clearing Price which shall be the same as the Current Reference Price, and (ii) The Near Clearing Price which shall be the same as the Current Reference Price" (Rule 4753(a)(3)(E)).
- The venue: The Early Order Imbalance Indicator contains "the same information as the Order Imbalance Indicator, except that it will exclude information about indicative prices" (Rule 4752(a)(1); Rule 4754(a)(10)).
- The engine: An auction's indication states three prices. The Near is what the cross would clear at over its own orders and the book trading on together; the Far, over the cross's own orders alone; the Current Reference Price, over the cross's own orders alone among the prices at or within the best bid and offer of the book trading on - the most shares paired, then the least imbalance, then the market's pressure, then the nearest the midpoint of that bid and offer, then as the uncross settles its last tie. The paired shares, the imbalance and its side are counted at the Current Reference Price. A Halt Cross's three are its one price. An indication the day asks for early states no Far and no Near.
- Judgement: "The entered price at which shares will remain unexecuted in the cross" is read as the market's pressure - the higher price where buyers are left over, the lower where sellers are - as the uncross reads it.
- Judgement: A side of the book trading on with no limit order leaves that bound of the Current Reference Price open; with neither side, or only one, it is drawn to the declared reference rather than a midpoint.
- Judgement: ITCH's Price Variation Indicator, "the absolute value of the percentage of deviation of the Near Indicative Clearing Price to the nearest Current Reference Price", is the one stated, where the rule's "percent by which the indicative prices are outside the then current Nasdaq Market Center best bid or best offer" is not: the venue's Ipc marks its bands. An early indication, with no Near, has none.
- Judgement: An Imbalance Only Order is counted among the cross's own orders, as the indicative counts it: the rule pairs OIO with the cross's orders.
- Not built: The "market buy" or "market sell" indicator of Rule 4752(a)(3)(E)(iii), for which ITCH's Net Order Imbalance Indicator has no field. A Halt or IPO Cross's Market Order Imbalance (Rule 4753(a)(2)), and the Current Reference Price its indicator leaves out where there is one, are the rule MarketOrderImbalance's; its tie-break to the IPO price, the last execution or the prior close (Rule 4753(a)(3)(A)(iv)) is the rule CrossTieBreak's.

**CrossTieBreak** - Nasdaq Equity 4, Rule 4752(d)(2)(D); Rule 4753(a)(3)(A)(iv), (b)(2)(D); Rule 4754(b)(2)(D); Rule 4120(a)(19)

- The venue: "If more than one price exists under subparagraph (C), the Nasdaq Halt Cross shall occur at: (i) In the case of an IPO, the price that is closest to the Issuer's Initial Public Offering Price; ... (iv) In the case of another halt type in which the security has already traded during Regular Market Hours on that trading day, the price that is closest to the last Nasdaq execution prior to the trading halt; (v) In the case of another halt type in which the security has not already traded during Regular Market Hours on that trading day, the price that is closest to the previous Nasdaq Official Closing Price" (Rule 4753(b)(2)(D)); the Halt Cross's Current Reference Price is ranked so too (Rule 4753(a)(3)(A)(iv)).
- The venue: "'Regular Market Hours' means the trading sub-session of the Day Session that operates from 9:30 a.m. until 4:00 p.m. or 4:15 p.m. on Business Days" (Rule 4120(a)(19)).
- The venue: The Opening Cross, at the same step: "the price that minimizes the distance from the bid-ask midpoint of the inside quotation prevailing at 9:30 a.m." (Rule 4752(d)(2)(D)); the Closing Cross: "a price that minimizes the distance from the System bid-ask midpoint at the time of the Nasdaq Closing Cross" (Rule 4754(b)(2)(D)).
- The engine: Where the most shares, the least imbalance and the market's pressure leave prices equal, each cross is drawn as the declaration's own Uncross for it says, in the place of the reference: the Halt Cross to the last price its security traded at from its Opening Cross, whose prints count, until its Closing Cross is done - to its declared reference where it has not traded since - and its indication's three prices with it. A cross the declaration names no Uncross of is drawn to its reference.
- The engine: A cross may be declared drawn to the midpoint of the best bid and offer of the book trading on, taken before what the cross collected joins it, and to its reference where that book has not both; its indication's Near and Far are drawn so too, and its Current Reference Price to that midpoint as before.
- Judgement: The declared reference stands for the previous Nasdaq Official Closing Price, as it does for the First Opening Reference Price, and for an IPO's Initial Public Offering Price: an IPO declares its reference at its offering price (ZXZZT's reference and IpoPrice are both $1.0000), and it trades nothing between the open and the IPO Cross that releases it.
- Judgement: Regular Market Hours are counted from the security's Opening Cross until its Closing Cross, rather than by the clock: the declared day is scaled, and a security halted through the open has its Opening Cross done as the open passes.
- Judgement: The Opening and Closing Crosses are declared drawn to the midpoint the rule states (the user's decision of 2026-11-20), not yet measured against Nasdaq's feed of 2026-08-20; the reference ordering the engine has by default was measured against Saudi Exchange's feed (9,481 of 9,484 indicatives, 2026-06-22), never Nasdaq's. The book trading on stands for the inside quotation, as for the Current Reference Price.
- Not built: The Halt Cross prices of a new listing that is no IPO - a security with recent trading in a Private Placement Market, one listing under IM-5315-2, or one that traded over the counter (Rule 4753(b)(2)(D)(ii), (iii), (vi)).

**LateLimitOrders** - Nasdaq Equity 4, Rule 4702(b)(9)(A) and (12)(A); Rule 4752(a)(8)-(9); Rule 4754(a)(9), (11)

- The venue: "Between 3:55 p.m. ET and immediately prior to 3:58 p.m. ET, an LOC Order may be entered provided that there is a First Reference Price or a Second Reference Price." "An LOC Order entered between 3:55 p.m. ET and immediately prior to 3:58 p.m. ET will be accepted at its limit price, unless its limit price is higher (lower) than the higher (lower) of the First Reference Price and the Second Reference Price for an LOC Order to buy (sell), in which case the LOC Order will be handled consistent with the Participant's instruction that the LOC Order is to be: (1) rejected; or (2) re-priced to the higher (lower) of the First Reference Price and the Second Reference Price, provided that if either the First Reference Price or the Second Reference Price is not at a permissible minimum increment, the First Reference Price or the Second Reference Price, as applicable, will be rounded (i) to the nearest permitted minimum increment (with midpoint prices being rounded up) if there is no imbalance, (ii) up if there is a buy imbalance, or (iii) down if there is a sell imbalance. The default configuration for Participants that do not specify otherwise will be to have such LOC Orders re-priced rather than rejected."
- The venue: "'First Reference Price' shall mean the Current Reference Price in the Early Order Imbalance Indicator disseminated at 3:50 p.m. ET"; "'Second Reference Price' shall mean the Current Reference Price in the Order Imbalance Indicator disseminated at 3:55 p.m. ET" (Rule 4754(a)(9), (11)).
- The venue: "Between 9:28 a.m. ET and 9:29:30 a.m. ET, an LOO Order may be entered, provided that there is a First Opening Reference Price or a Second Opening Reference Price", accepted, rejected or re-priced in the same words (Rule 4702(b)(9)(A)); "'First Opening Reference Price' shall mean the previous day’s Nasdaq Official Closing Price of the security"; "'Second Opening Reference Price' shall mean the Current Reference Price in the Order Imbalance Indicator disseminated at 9:28 a.m. ET" (Rule 4752(a)(8)-(9)).
- The engine: The day keeps each cross's reference prices as its chart says: the Current Reference Price of the cross's indication as the day enters PreClose and ClosingLockOut, and the security's declared reference as it enters PreOpen and the Current Reference Price as it enters OpeningLockOut. A Current Reference Price that pairs no shares is no reference price. A late LOC in ClosingLockOut, or LOO in OpeningLockOut - priced, and not imbalance only - with neither of its cross's reference prices is rejected, OUCH 0x000E for the LOC and 0x0014 for the LOO; one to buy (sell) priced above the higher (below the lower) of them is rejected 0x0019 where its port instructs so (the declaration's Client LateLimitOnClose or LateLimitOnOpen Reject), and otherwise re-priced to that price and accepted at it. A price off its increment is rounded up where the cross's indication at entry has buyers left over, down where it has sellers, and to the nearer increment, a midpoint up, where it has neither.
- Judgement: The rule's "if there is no imbalance", or a buy or a sell imbalance, is read as the imbalance the cross's indication states as the order arrives - its Current Reference Price's - rather than that of the indication a reference price was kept from: the First Opening Reference Price was kept from none.
- Judgement: The reference prices are kept as the day changes phase, standing in for the indications "disseminated at" 3:50, 3:55 and 9:28, which the day's own requests for an indication may follow by a tick of its clock.
- Judgement: The First Opening Reference Price is the security's declared reference, which stands in for its previous day's Nasdaq Official Closing Price in every day the simulator runs.
- Judgement: OUCH 5.0 names "0x000E No Closing Reference Price" and "0x0019 Late LOC Too Aggressive" and no condition for either (Appendix C), and no code for a late LOO: one with no opening reference price is rejected 0x0014 Invalid Cross Order, and one too aggressive 0x0019.
- Judgement: An LOO entered after 9:29:30 is outside the rule's window and is not checked: the rule states only that one "designated as an IOC will be rejected", which the day does.
- Not built: A replace of a late LOC or LOO, which the day takes for its cross as it was without checking its new price; an early close's reference times.

**CrossBenchmarks** - Nasdaq Equity 4, Rule 4752(d)(2)(E); Rule 4754(b)(2)(E)

- The venue: "If the Nasdaq Opening Cross price established by subparagraphs (A) through (D) is outside the benchmarks established by Nasdaq by a threshold amount, the Nasdaq Opening Cross shall occur at a price within the threshold amounts that best satisfies the conditions of subparagraphs (A) through (D). Nasdaq management shall set and modify such benchmarks and thresholds from time to time upon prior notice to market participants." (Rule 4752(d)(2)(E))
- The venue: "If the Nasdaq Closing Cross price established by subparagraphs (A) through (D) above is outside the benchmarks established by Nasdaq by a threshold amount, the Nasdaq Closing Cross will occur at a price within the threshold amounts that best satisfies the conditions of subparagraphs (A) through (D) above." (Rule 4754(b)(2)(E))
- The engine: A cross the declaration gives a CrossBenchmarks is asked its price - each indication as it collects, and its uncross - only among the prices within its declared percent of its declared benchmark, rounded in to a tick: its Reference, or the Midpoint of the best bid and offer of the book trading on, its reference where that book has not both. Within them the cross decides as it always does, so it occurs at the price within the thresholds that best meets steps (A) through (D). A cross with no benchmark to measure from, and one the declaration gives none, is held to no threshold.
- Judgement: The benchmarks and thresholds are Nasdaq management's and are not in the saved rules; each is declared, and the declaration's numbers are the simulator's, not Nasdaq's. The declared reference stands for the previous Nasdaq Official Closing Price, as it does elsewhere.
- Judgement: A cross's indications are held within its thresholds too, so the Near Clearing Price and the Current Reference Price state the price the cross would occur at.
- Not built: A threshold as an amount rather than a percent of its benchmark.

**OpeningCrossPriceTests** - Nasdaq Equity 4, Rule 4752(d)(2)(F)

- The venue: "each security in the Nasdaq Opening Cross must also pass one of the Opening Cross Price Tests in subparagraphs (i) through (iii) below or all MOO, LOO, OIO, and Early Market Hours orders in the Nasdaq Opening Cross in the security will be cancelled back to Participants, no Nasdaq Opening Cross in that security will occur, and the security will open for Regular Market Hours trading consistent with paragraph (c) above." "Nasdaq will establish and publish the thresholds used in the Opening Cross Price Tests below."
- The venue: Test A's range is set "by adding and subtracting the Opening Cross Price Test A threshold from the Nasdaq Official Closing Price of the security for the previous trading day"; Test B's "from the Nasdaq last sale (either round or odd lot) after 9:15 a.m. ET but prior to the Opening Cross", "or if there is no Nasdaq last sale, Opening Cross Price Test C will be performed"; Test C's "from the Nasdaq best bid (for Opening Cross prices that would be higher than the price used under subparagraph (i) above) or Nasdaq best offer (for Opening Cross prices that would be lower than the price used under subparagraph (i) above)", and "if a security does not have a Nasdaq Official Closing Price ... Nasdaq will use a price of $0" (Rule 4752(d)(2)(F)(i)-(iii)).

However, the System may, based upon its proprietary assessment of market conditions for that symbol, decide to vary the default Holding Period of all Midpoint Extended Life Orders in a symbol in increments of 0.25 or 0.50 milliseconds, and within an overall range of between 0.25 and 2.50 milliseconds during normal market conditions (described below), beginning 30 seconds after Regular Market Hours commences and then at 30 second intervals thereafter until Regular Market Hours conclude (“Change Events”)"; and "whenever the System determines that market conditions for a symbol have become extraordinarily unstable ... the System will activate a stability protection mechanism", which will "immediately increase the duration of the Holding Period to 12 milliseconds for a period of at least 750 milliseconds" (Rule 4702(b)(14)(A)).
- The venue: "If a limit price is assigned to a Midpoint Extended Life Order, the Order will be: (1) eligible for execution in time priority if upon acceptance of the Order by the System, the midpoint price is within the limit set by the participant; or (2) held until the midpoint falls within the limit set by the participant at which time the Holding Period will commence and thereafter the System will make the Order eligible for execution in time priority." "If a Midpoint Extended Life Order has met the Holding Period requirement but the midpoint is no longer within its limit, it will nonetheless be ranked in time priority among other Midpoint Extended Life Orders and M-ELO+CBs if the NBBO later moves such that it is within the Order's limit price. Midpoint Extended Life Orders will not execute if there is a resting non-displayed Order priced more aggressively than the midpoint between the NBBO, and will be held for execution until the resting non-displayed Order is no longer on the Nasdaq Book or the midpoint of the NBBO matches the price of the resting non-displayed Order." (Rule 4702(b)(14)(A)).
- The venue: "Midpoint Extended Life Orders in existence at the time a halt is initiated will be ineligible to execute and held by the System until trading has resumed and the NBBO has been received by Nasdaq. Upon resumption of trading in a halted symbol, any new Midpoint Extended Life Order in that symbol and any pending Midpoint Extended Life Order in that symbol with an unexpired Holding Period will be subject to a 12 milliseconds Holding Period (running from the time when trading resumes) until the next scheduled Change Event"; "the Holding Period will commence only if, upon commencement of trading following the Halt, the midpoint price for the Order is within the limit set by the participant. If not, the System will hold the Order until the midpoint falls within the limit set by the participant, at which time the 12 millisecond Holding Period will commence." (Rule 4702(b)(14)(A)).
- The venue: "Time-in-Force. Regardless of the Time-in-Force entered, a Midpoint Extended Life Order may not be active outside of Regular Market Hours. A Midpoint Extended Life Order entered during Pre-Market Hours will be held by the System in time priority until Regular Market Hours. Midpoint Extended Life Orders entered during Post-Market Hours will not be accepted by the System. A Midpoint Extended Life Order remaining unexecuted after 4:00 p.m. ET will be cancelled by the System. Midpoint Extended Life Orders designated for the Night Session will be rejected. If a Midpoint Extended Life Order is entered with a Time-In-Force of IOC, it will execute against available eligible resting interest immediately upon the expiration of the Holding Period; if no such resting interest is available, or shares of the Order remain unexecuted after executing against eligible resting interest, then the System will automatically cancel the Order or the remaining shares of the Order, as applicable; if the Order is ineligible to begin the Holding Period upon entry, then the System will cancel it immediately." "Non-Display. All Midpoint Extended Life Orders are Non-Displayed." (Rule 4702(b)(14)(B)).
- The venue: "A M-ELO+CB that satisfies the Holding Period shall be eligible to execute (at the midpoint of the NBBO) against other eligible M-ELO+CBs, eligible Midpoint Extended Life Orders, and as described below, Non-Displayed Orders with Midpoint Pegging("Midpoint Pegging Orders") resting on the Exchange's Continuous Book. A M-ELO+CB shall be eligible to execute against a Midpoint Pegging Order if: (i) the Midpoint Pegging Order has the Trade Now Attribute enabled; (ii) no other order is resting on the Continuous Book that has a more aggressive price than the current midpoint of the NBBO; (iii) the Midpoint Pegging Order has rested on the Exchange's Continuous Book for a minimum of the duration of the Holding Period then applicable to a M-ELO+CB in that symbol after the NBBO midpoint falls within the limit set by the participant; and (iv) the Midpoint Pegging Order satisfies any minimum quantity requirement of the M-ELO+CB. A buy (sell) MELO+ CB will be ranked in time order at the midpoint among other buy (sell) MELO+ CBs, buy (sell) Midpoint Extended Life Orders, and buy (sell) Midpoint Pegging Orders, as of the time when such Orders become eligible to execute." (Rule 4702(b)(15)); Trade Now allows "(ii) a Non-Displayed Order with Midpoint Pegging to execute against a M-ELO+CB automatically", "after the Midpoint Order rests on the Continuous Book for a minimum of one-half second after the NBBO midpoint falls within the limit set by the participant" (Rule 4703(m)).
- The venue: "All Order Types except Midpoint Peg Post-Only Orders and Supplemental Orders and Midpoint Extended Life Orders and M-ELO+CBs participate in the Nasdaq Opening Cross and/or the Nasdaq Closing Cross" (Rule 4703(l)); OUCH 5.0's Cross Type "E = extended life (Nasdaq only)" (p. 5), HandleInst "B = Extended Life + Continuous (CrossType E)" (p. 22), and Liquidity Flag "n Midpoint Extended Life Order execution" (p. 25).
- The engine: An order for it alone (CrossType E, the Ipc's ExtendedLife) is taken into a book of its own, never shown and never in a cross, by every phase from the pre-market to the close - its chart's Send.Book.Life - and refused as for its cross (Reason Cross) post-market. Its time in force is not read but for IOC.
- The engine: Its holding period - the declared HoldingMicroseconds - begins as it is accepted where the book's hours have started its kind (Send.Life.Start at the open) and the midpoint of the best bid and offer the book shows is within its limit; otherwise when they first are. As a halt begins (Send.Life.Stop) every one is held; as it is lifted (Send.Life.Start, Holding 'Resumed') each whose period had not passed begins the declared ResumedHoldingMicroseconds, and one already eligible stays so.
- The engine: Each time the day's clock is handed, those whose period has passed and whose limit the midpoint is within trade with each other at the midpoint - a midpoint between two prices taken at the lower - unless an order resting unseen is priced beyond it: ranked by when each became eligible, each against those ranked before it on the other side, the earlier first, the later the aggressor. A Minimum Quantity order trades only with an order whose size meets its minimum. Then what is left of an eligible M-ELO+CB (HandleInst B, the Ipc's Extended Life Book, Continuous) trades with the Trade Now midpoint pegs on the other side resting at the midpoint, in the order the book ranks them, each that has rested there a holding period and whose size meets its minimum, as the aggressor. What is left of an eligible IOC one is then canceled, and an IOC one that cannot begin its period as it arrives is canceled at once.
- The engine: A cancel takes one out at any time; a reduce lowers it where it stands, keeping its period and its rank; a replace takes it out and its replacement begins a period anew. At the close - a Send.Book.Expire of the Cross 'ExtendedLife' with each Close - what is left of every one is canceled. Each of its fills is flagged as one in the Ipc's Auction, Extended Life.
- Judgement: The holding period is declared, <MidpointExtendedLife><HoldingMicroseconds>1250</HoldingMicroseconds><ResumedHoldingMicroseconds>12000</ResumedHoldingMicroseconds></MidpointExtendedLife> on the Engine, the rule's initial 1.25 ms and its 12 ms after a halt. Nasdaq's proprietary variation at Change Events and its stability protection mechanism are not reproduced: the holding period never changes, and a new order after a halt takes the declared period, not 12 ms until the next Change Event.
- Judgement: The NBBO is the book's own best bid and offer, of shown orders, as a Midpoint Peg's is here: the simulator has no other market. The resolution is the declared clock tick: periods begin, end and trade only as the day's clock is handed, so a 1.25 ms period ends up to a tick late, and an order is eligible to trade once now is at or past its period's end.
- Judgement: Holding periods begin at the open for what was held pre-market, the rule saying only that those are "held ... until Regular Market Hours". Orders entered while halted are held, as those in existence are. An IOC one entered pre-market or halted cannot begin its period on entry and is canceled at once. An unpriced one (OUCH's market price) has no limit, and the midpoint is always within it. Its OUCH Time in Force otherwise changes nothing.
- Judgement: Rank is by when each became eligible - the end of its holding period - for a M-ELO as Rule 4702(b)(15) states it for a M-ELO+CB; ties in the order they were accepted. A M-ELO+CB meets the others of its kind before any Trade Now midpoint peg, rather than all ranked together, and a peg trades only where it stands exactly at the midpoint: one priced at a midpoint between two prices never does.
- Judgement: A Trade Now midpoint peg must have rested at the midpoint for the declared holding period, as Rule 4702(b)(15)(iii) says, not the "minimum of one-half second" of Rule 4703(m), which the two rules state differently; its rest is counted, by the day's clock, from when the clock first finds it at the midpoint, and starts again once its limit holds it away. Its own minimum quantity must be met too.
- Judgement: A post-market M-ELO is rejected OUCH 5.0's 0x0014 Invalid Cross Order, OUCH naming no code of its own; what is left at the close is canceled by its time in force's reason, a Day one 'T' Timeout. Every side of a fill in it is flagged 'n', the M-ELO+CB's Trade Now peg too. Each fill is printed on ITCH as a Trade Message, non-cross and non-displayed, at the midpoint - none of its orders is ever shown - and does not set the book's last sale. The orders of one owner are not kept from matching each other in it.
- Not built: The Change Events and the stability protection mechanism (proprietary). The Night Session's rejection. The modification of a sell's long, short or short exempt marking, which OUCH's Replace does not carry: a replace always restarts the period. A M-ELO entered through FIX, whose order message here carries no extended life cross. The weekly and monthly statistics Nasdaq publishes.

**SelfMatchPrevention** - Nasdaq Equity 4, Rule 4757(a)(4)

- The venue: "Market participants may direct that quotes/orders entered into the System not execute against either quotes/orders entered under the same MPID or quotes/orders entered across MPIDs under Common Ownership", and may "assign to orders entered through a specific order entry port a unique group identification modifier that will prevent quotes/orders with such modifier from executing against each other".
- The engine: Two orders of one owner that would trade as one arrives do not: by the strategy of the order removing liquidity the newer is canceled, the older, both, or each is lowered by what would have traded. Nothing is prevented in a cross.
- Judgement: An owner is kept within the Account its orders came in on, the port (OUCH 5.0, 1.1): the simulator has no record of which ports are one MPID's.

**TradeNow** - Nasdaq Equity 4, Rule 4703(m)

- The venue: Trade Now "allows: (i) a resting Order that is locked or crossed, as applicable, at its non-displayed price by the posted price of an incoming Displayed Order or a Midpoint Peg Post-Only Order or another Order or Orders (where such locking or crossing Order(s) or the order with Trade Now satisfies a Minimum Quantity condition) to execute against a locking or crossing Order(s) as a liquidity taker automatically when such Orders become marketable", and "Any remaining shares of the resting Order will remain posted on the Nasdaq Book with the same priority".
- The engine: As an order posts, each order the book does not show on the other side that carries the attribute and is locked or crossed by it takes it, best price first and in time order, at the prices of the orders it takes - where it names a minimum, only once that much is there - and what is left of it stays where it rests.
- Judgement: It is looked for only as an entered order posts, not as one is priced anew.
- Not built: The rule's second part, a Midpoint Pegging order executing against a M-ELO+CB, is the rule MidpointExtendedLife's: an engine stating no such rule has no M-ELO+CB. Its "minimum of one-half second" is not this rule's: see that rule's Judgement.

**Reserve** - Nasdaq Equity 4, Rule 4703(h)

- The venue: "the full size of the Order will be presented for potential execution"; "if the remaining total size is less than the display size stipulated by the Participant, the Displayed Order will post without Reserve Size"; when an execution causes the displayed size "to decrease below a normal unit of trading, another Displayed Order will be entered at the limit price and size stipulated by the Participant", and "The new Displayed Order will receive a new timestamp".
- The engine: An order posts showing its floor where it has more than that. A fill takes only what it shows; once that is spent it is shown again from what is behind it, at the back of the shown orders at its price and under a new id, which its feed publishes as a new order and its owner is told as Order Restated. Lowering it comes off what is behind its floor first.
- Judgement: The rule refreshes as the displayed size falls below a normal unit of trading, what is left of it staying beside the new order; here it is refreshed once it is spent.
- Judgement: The rule ranks the non-displayed part as a non-displayed order; here it trades only through what it refreshes, so behind every shown order at its price and ahead of the unseen ones.
- Judgement: In a cross it trades its whole size where it stands, what was not shown told as not shown.
- The venue: A Participant may stipulate "a Random Reserve": "The actual displayed size will then be randomly determined by the System from a range of normal trading units in which the minimum size is the nominal displayed size minus the range size, and the maximum size is (i) the minimum size plus (ii) an amount that is two times the range size minus one round lot." OUCH 5.0: RandomReserves (tag 13), "Shares to do random reserve with".
- The engine: An order with a RandomReserves range shows, each time it posts or is shown again, a number of round lots drawn from its floor less the range up to that plus twice the range less one round lot; a range of none, or of no less than its floor, shows its floor. The draw comes from the id it is shown under, so a venue started again from its journal draws the same.
- Not built: The liquidity flag u.
- Measured: Nasdaq's TotalView-ITCH feed of 2026-08-20, the whole day (898,523,816 messages): 206,231 of the 10,094,128 orders executed away are followed, as their security's next message, by an add on the same side at the same price - 123,063 of them a round lot, 202,410 within a millisecond, none attributed. Consistent with a refresh being a new Add under a new reference; the feed does not say which of them are reserve orders.

**ShortSaleTest** - Nasdaq Equity 4, Rule 4763; Rule 201 of Regulation SHO

- The venue: The System "shall not execute or display a short sale order with respect to a covered security at a price that is less than or equal to the current national best bid"; "short sale orders that are limited to the national best bid or lower and short sale market orders will be re-priced by the System one minimum allowable price increment above the current national best bid"; and IOC orders "will be executed to the extent possible at a Permitted Price and higher and then cancelled, and will not be re-priced".
- The engine: While its security is under the test a short sale priced at or below the best bid the book shows, or unpriced, is priced an increment above it before it is taken; an IOC one trades only above the bid and is canceled. A short sale exempt, OUCH's Side E, is held to nothing.
- Judgement: The national best bid is the book's own best shown bid: the simulator has no other market.
- The venue: "To reflect declines in the national best bid, the Exchange will continue to re-price a short sale order at the lowest Permitted Price down to the order's original limit price."
- The engine: A short sale the test repriced follows a falling bid down to the limit it was entered at, each time a new priority under a new id, its owner told an Order Priority Update and the feed an Order Replace where the book shows it; never up. It is done as an order arrives, so a bid that falls for the moment between a cancel and a new order - as the venue's own makers requote - reprices it too.
- Not built: Repricing upward of a non-displayed short sale as the bid rises; the test's own trigger, a fall of 10% from the prior close, in whose place the declaration says whether a day starts under it; a short sale entered for a cross.
- Measured: Nasdaq's TotalView-ITCH feed of 2026-08-20, the whole day (898,523,816 messages): the Reg SHO Restriction of the start of day spin is 0 for 12,721 securities and 2 for 432, and 399 more Reg SHO Restriction messages of action 1, the test put in place, follow in the day.

**FatFingerProtection** - Nasdaq Equity 6, Section 5(m)

- The venue: "The Exchange offers certain risk settings applicable to a Participant's activities on the Exchange", among them "(m) Fat Finger Protection - This control relates to the price of an order by evaluating whether the limit price is set too aggressively through the NBBO (percentage-based and dollar-based controls are available)" (Equity 6, Section 5).
- The venue: OUCH 5.0's Rejected Order Reason "0x0026 Risk: Fat Finger" (Appendix C).
- The engine: A client that declares a FatFingerProtection - a Percent of the book's best opposite price, Dollars, or both - has each order and replace it enters carried to the engine with them (the Ipc's Protection Percent and Protection Amount, 0 for none). A limit order to buy priced above the best offer by more than that, or to sell below the best bid by more, is rejected 0x0026 rather than taken; with both declared, the tighter applies. It is checked where a phase takes the order to trade as it arrives, before it trades, and a replace before the order it replaces leaves the book, so a replace refused leaves that order standing.
- Judgement: The book's best shown bid and offer stand for the NBBO: the simulator has no other market.
- Judgement: A setting of the Participant's, so declared of each client; a client that declares none is held to nothing.
- Judgement: Not checked: an order where the other side shows nothing, a market or pegged order - its price is the engine's - an order for a cross, which trades at its cross's price rather than through the quote, and any order in a phase that holds orders for an auction or a halt rather than trading them as they arrive. A discretionary order is measured by its limit price, not its discretion price. A replace that only lowers an order's quantity where it rests keeps its place and is not checked.
- Judgement: Measured before the venue's own Limit Order Protection, as the Participant's risk settings are the port's.
- Not built: A refused replace is answered 0x0015 Replace Not Allowed, as every replace the engine refuses is, not 0x0026: a response tells the refusal's reason apart or the request it answers, not both. A FIX client's orders carry no protection: the FIX gateway does not fill it.

**LimitOrderProtection** - Nasdaq Equity 4, Rule 4757(c)

- The venue: "LOP is a feature of the Nasdaq Market Center that prevents certain Limit Orders at prices outside of pre-set standard limits ("LOP Limit") from being accepted by the System."
- The venue: "LOP applies to all Quotes and Orders, including Quotes and Orders that have been modified, where the modification results in a new timestamp and priority. LOP does not apply to Orders with Market and Primary Pegging, Market Maker Peg Orders or Intermarket Sweep Orders. A Midpoint Pegging Order with a discretion price would not be subject to LOP. LOP is operational each trading day, except for orders designated for opening, reopening and closing crosses and initial public offerings. LOP is not operational during trading halts and pauses. LOP would not apply in the event there is no established LOP Reference Price or the National Best Bid, when used as the LOP Reference Price, is equal to or less than $0.50." (Rule 4757(c)(i))
- The venue: "The LOP Limit shall be the greater of 10% of the LOP Reference Price or $0.50 for all securities across all trading sessions." "The LOP Reference Price shall be the current National Best Bid or Best Offer, the bid for sell orders and the offer for buy orders." "The LOP Reference Threshold for buy orders will be the LOP Reference Price (offer) plus the applicable LOP Limit. The LOP Reference Threshold for sell orders will be the LOP Reference Price (bid) minus the applicable LOP Limit." "Limit Orders will be rejected if the price of the Limit Order is greater than the LOP Reference Threshold for a buy Limit Order. Limit Orders will be rejected if the price of the Limit Order is less than the LOP Reference Threshold for a sell Limit Order." (Rule 4757(c)(ii)-(v))
- The engine: Every client's limit order to buy priced above the best offer plus the LOP Limit, or to sell below the best bid less it, is rejected rather than taken - the limit the greater of the declaration's Percent of that price and its Dollars (its Engine's LimitOrderProtection: 10% and $0.50; a declaration stating none holds no order to it). A sell is not held to it while the best bid is at or below the declaration's UnprotectedBid ($0.50). A pegged order is not held to it - Market and Primary Pegs, and a Midpoint Peg with a discretion price - but a Midpoint Peg without one is, by the limit it states; one stating none is not. It is checked where a phase takes the order to trade as it arrives, after the client's Fat Finger Protection, and a replace before the order it replaces leaves the book.
- Judgement: The rule names no OUCH code: an order it rejects is OUCH 5.0's "0x0006 Fat Finger" (Appendix C), the venue's own price protection, kept apart from the Participant's 0x0026.
- Judgement: The book's best shown bid and offer stand for the NBBO, the LOP Reference Price; a side showing nothing is no established LOP Reference Price.
- Judgement: "operational each trading day, except for orders designated for opening, reopening and closing crosses and initial public offerings" and "not operational during trading halts and pauses" are read as: not checked for an order for a cross, nor in any phase that holds orders for an auction or a halt rather than trading them as they arrive - the pre-open's held orders, a halt's, a pause's and an IPO's quotation period. A market order is not a Limit Order and is not checked. A Market Maker Peg is refused for its peg before it is measured.
- Judgement: Its numbers are the rule's own, declared once for the venue rather than written into the generator.
- Not built: An Intermarket Sweep Order is held to it: the Ipc does not carry OUCH's Intermarket Sweep Eligibility. A refused replace is answered 0x0015, as the FatFingerProtection rule says.

**EntryPriority** - Nasdaq Equity 4, Rule 4757(a)(1)

- The venue: The price/display/time algorithm: "Equally priced Orders with a Display Attribute will be ranked in time priority".
- The engine: Orders at a price rank by when each took its place there. An order collected while an auction collects - a Day order entered before the open, held for the Opening Cross - joins the book as the cross completes in the time priority of its entry, ahead of an order that took its place after it, as an order resting since before the open would. An order taking a new place - shown again from its reserve, repriced, replaced - ranks from then.
- Measured: Nasdaq's TotalView-ITCH feed of 2026-08-20: USAR's buys at $17.75 entered before the open were added at 09:30:00.089071507, after the Opening Cross, and the sell that swept the level at 09:30:00.1007 took them in the order of their references - 434772 first - before order 108493928, shown at 09:28:17. Over the whole day, each of the 29,804 executions that took an order behind the one an engine ranking by arrival would have traded first took one of a lower reference, an order entered earlier.

## Build

Requirements: C++20, CMake 3.28+, Boost, and a standard library with the C++20 time zone database - GCC 14 or newer (g++-14, `-DCMAKE_CXX_COMPILER=g++-14`; Ubuntu 24.04's default g++ is 13) - with tzdata installed

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

## Run

```bash
./build/nasdaq_simulator                # endpoints from simulator.ini
./build/nasdaq_simulator --config my.ini
./build/simulator_tests              # Boost.Test suite
./build/simulator_tests_fix  # the Fix order entry's own suite
```

Runtime endpoints are read from simulator.ini at process start:

| Connection | Default |
| --- | --- |
| Order entry (Tcp) | 127.0.0.1:15101 |
| Fix order entry (Tcp) | 127.0.0.1:15117, 15118 |
| TotalView feed (Udp multicast) | 233.54.12.112:26478 |
| Glimpse snapshot (Tcp) | 127.0.0.1:15102 |
| TotalViewTcp stream (Tcp) | 127.0.0.1:15103 |

Recording output (order-entry log, market data captures) lands under `recordings/`.

## State check

`nasdaq_state_check` holds the engine's priority to a captured day of the venue's own TotalView feed:

```bash
./build/nasdaq_state_check [--port <udp port>] <capture.pcap> ...
zstd -dc day/*.pcap.zst | ./build/nasdaq_state_check -
```

Every order the venue showed is held in its security's engine, placed as the engine places a
shown order, and each execution the venue reported of a resting order is set beside the order
the engine would have traded first on that side: the first at the best price. Where the venue
took another, the report says whether it stood at the best price behind others or at a worse
one. Interest the feed never shows - hidden and reserve size, midpoint pegs, on-open and
on-close orders - trades without an order on it, so the venue's crosses are not checked: the
interest that decides them is not on the feed.

## Book check

`nasdaq_book` holds the book the venue's TotalView feed builds against the engine's own.
The book is generated from the book model Nasdaq.NsmEquities.Equities (`common/book/`), and each feed message
the model binds to an operation is applied to it. Run the venue with its book written as it goes -
`[book] dump = book.csv` and `every = phase`, or a number of milliseconds - then:

```bash
./build/nasdaq_book recordings/marketdata/TotalView.dat book.csv
```

Each time the engine was asked for its book, the feed's recorder marked where in the feed the
answer belongs (`TotalView.dat.books`). At each mark the two books are compared: the same orders,
each on the same side at the same price for what the engine's book shows of it, and at each price
in the order the engine would fill them. What the engine holds and does not show - a hidden
order, the rest of a reserve order - is no part of a book built from the feed, and is not compared.
